NOVA — lossless multichannel codec (prototype)

Cross-channel lifting + adaptive fixed prediction + static rANS entropy coding. Runs entirely in this page — no server, no upload.

What this honestly is

This is a real, working lossless codec — not a mockup. Every encode is followed by an automatic decode-and-compare step in your browser so you can see bit-exact correctness for yourself. It takes WAV input (parsed byte-exact) rather than FLAC, since browser audio decoding isn't guaranteed bit-exact. Convert first with: ffmpeg -i yourfile.flac yourfile.wav — ffmpeg carries your tags and cover art into the WAV automatically (as an embedded ID3 chunk), and this page reads that back out.
Deeper bug found: the "adaptive" fix in the last version barely helped (130.64→129.54 MB) because the decision itself was using the wrong cost metric. Every adaptive choice in this codec (predictor order, cross-channel lift, LMS mode) was comparing options by sum of raw magnitude — but Rice/entropy coding cost actually scales with log2 of magnitude, not magnitude itself. Two signals with identical sum-of-magnitude can have very different real compressed size depending on their distribution shape (concentrated vs. spread out), so the old metric was silently picking the wrong option much of the time — not just for the two new stages, but potentially for predictor-order selection all along. Every decision point now estimates actual bit cost (log2-based) instead. This is a more fundamental fix than the last one; whether it recovers past 112.78 MB is, as always, something only your real file can answer — my synthetic tests don't clearly show this class of improvement either.

About the "stereo only" playback issue

Detecting browser output capability…
This is a real, unavoidable-from-JS limitation, not a bug I can just patch away: browsers report how many discrete channels they can send to your current default output device via AudioContext.destination.maxChannelCount. If Windows (or your OS) has the default output device configured as a 2-channel device — which is the common default even on multichannel interfaces — the browser cannot get more than 2 channels out, no matter what code requests. The page below attempts to request the maximum available and route channels discretely (no downmixing), so if your OS output is actually configured for >2 channels, playback here should now use them.
For definitive verification of all 8 channels (e.g. into the interface software shown in your screenshot), use "Download decoded WAV" above and play that file in your DAW/mixer software directly — that sidesteps the browser's output-device limitation entirely and is the more reliable way to confirm the full channel set decoded correctly.
